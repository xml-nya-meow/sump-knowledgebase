## 先认识这一条主路线

```text
用户输入
→ frontend 或 qq 接收
→ reasoner 请求 memory 准备上下文
→ memory 回送 resume
→ reasoner 请求模型
→ 按模型请求与服务契约调用工具
→ 收集普通结果，或登记异步工作并等补报
→ 判断下一步与收尾条件
→ deliver 回入口，呈现给用户
```

实际业务会有分支。例如模型可以直接回答；外部 MCP 调用可以直接进入已导出的工具；计时结果可能在首次答复之后才到。第 06 章会分别画出这些中间状态。

## 本版阅读时尤其要分开的几件事

| 常见混淆 | 本组课程怎样解释 |
| --- | --- |
| 中心像总交换机 | 中心提供名册与设置，业务通常直连目标 |
| `ok:true` 就是整件事完成 | 查明它确认的是请求、受理、应用还是最终结果 |
| 所有 `queued` 都表示真实排队 | shell/timer 当前回执用这个词，但没有因此提供 FIFO 等待队列 |
| batch 能自动批量跑一切工具 | 本快照正式服务尚未开启 Batchable；示例明确标为测试夹具 |
| 有历史就能恢复全部任务 | 持久档案与在途黑板/句柄是不同状态 |
| 存下图片就等于理解图片 | images 存取；reasoner 获取并交给支持图片的模型 |
| 工具导入后自然可以对外调用 | MCP 导入与导出独立授权 |
| 取消本地等待就停止远端执行 | 分开描述观察、调用、执行三层生命周期 |

这些区分来自当前实现的阅读，不是为项目新加的一套架构。

## 这些说明是怎样核对的

本次阅读了固定提交中的实现、依赖文件、动作声明、协议结构和相关测试定义；核查了文档链接与引用的源码位置。各章明确区分教学模拟、源码行为和运行证据。

## 阅读小提示

- 先看一句话解释，再看例子，最后看源代码链接。
- 图不能显示时，读图前后的文字路线和表格即可。
- JSON 示例若写着“正文示意”，只表示字段形状，不能直接当完整原生网络消息发送。
- 看到“来源”“编号”时，不要自动把它理解成认证或权限。
- 看见不懂的词，到第 08 章查一次，再回原场景。
